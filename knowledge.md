# Mémo technique — Wonderland’s War Web

À consulter avant de commencer une issue ou de retenter une commande qui a échoué. Pour chaque nouveau problème utile à retenir, noter le symptôme, la cause si elle est connue, la correction et la vérification. Signaler explicitement les blocages encore ouverts.

## Problèmes rencontrés

| Symptôme | Correction ou précaution | Vérification |
|---|---|---|
| Les instructions mentionnaient GitLab alors que le projet est sur GitHub. | Vérifier `git remote -v` avant toute écriture distante. Utiliser `gh` avec `--repo FlowHartigan/alice_wonder` lorsque la commande le permet. | `origin` et `gh repo view` ont confirmé le même dépôt. |
| Git indiquait `No commits yet` et `origin/main [gone]` avant la publication du socle [#1](https://github.com/FlowHartigan/alice_wonder/issues/1). | Vérifier les branches réellement publiées avec `git ls-remote --heads origin`. Les issues peuvent être créées sans branche, mais une PR attend une base publiée. | **Résolu :** `git fetch origin main` puis `git rev-parse origin/main` ont confirmé le socle `5bfa697` pour [#37](https://github.com/FlowHartigan/alice_wonder/issues/37). |
| `user.name` et `user.email` ne sont pas configurés pour créer un commit. | Fournir `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_COMMITTER_NAME` et `GIT_COMMITTER_EMAIL` dans le processus qui exécute Git (identité autorisée et adresse GitHub `noreply`). Ne modifier aucune configuration Git. | Le commit de [#37](https://github.com/FlowHartigan/alice_wonder/issues/37) a été créé avec ces variables ; `git show` confirme l’auteur et le committer, et `git config --get` ne renvoie toujours aucune des deux clés. |
| L’appel `task` a renvoyé `Unknown agent type: github-issue`, alors que l’agent est configuré. | Distinguer les agents reconnus par OpenCode des types exposés par l’outil `task` de la session. Redémarrer OpenCode après modification de `.opencode/`. Si le type nommé est toujours indisponible, déléguer à un type disponible avec le rôle du fichier agent explicite et ne pas présenter ce relais comme un appel natif. | `opencode.cmd agent list` reconnaît les trois agents ; le relais `general` a permis de créer et de vérifier le backlog. |
| Une session en mode Plan ne permettait pas d’appliquer les fichiers. | Passer en mode **Build** avant d’écrire (`Tab` dans le terminal OpenCode) et vérifier le mode affiché. | Les fichiers d’agents et la commande `/evolution` ont ensuite été chargés par OpenCode. |
| Le téléchargement du livret FR via `webfetch` dépassait la limite de 5 Mo ; la commande `python` ouvrait le raccourci Microsoft Store. | Télécharger le PDF officiel dans le dossier temporaire approuvé avec `curl.exe`. Pour les tableaux en pictogrammes, consulter la page rendue : l’extraction de texte ne suffit pas. | Pour [#2](https://github.com/FlowHartigan/alice_wonder/issues/2), le PDF en cache et la pièce jointe éditeur retéléchargée ont le même SHA-256. Lire le PDF comme pièce jointe locale a fourni le rendu : les pictogrammes p. 5 ont été comptés visuellement. Ni le PDF ni son rendu ne sont ajoutés au dépôt. |
| Sous Windows PowerShell 5.1, le texte français passé par un pipe à Node peut perdre ses accents et tirets Unicode. | Avant d'envoyer du texte à une commande native sur son entrée standard, utiliser `$OutputEncoding = [System.Text.UTF8Encoding]::new($false)` dans le processus courant. | Node a reçu `Éclats — 2J` intact avec ce réglage. |
| PowerShell traite aussi l’apostrophe typographique `’` comme un délimiteur dans une chaîne entre apostrophes. | Reformuler le message de commit sans apostrophe ou utiliser des guillemets doubles. Pour un corps de PR Markdown, utiliser `gh pr create --body-file`. | Commit de #6 lancé avec un titre sans apostrophe et PR préparée à partir d’un fichier UTF-8. |
| Docker n’était pas disponible dans le `PATH` pendant le prototype. | Pour la recette locale, utiliser SQLite via `node:sqlite` et la version Node du projet (`>=24`). Voir `docs/decisions.md` pour la cible PostgreSQL. | Le test de réouverture de la base a retrouvé la place, le statut et l’idempotence. |
| TypeScript signalait `TS7053` après `socket.timeout(...).emitWithAck(...)` : la réponse devenait `any`. | Pour les appels à délai commun, régler `ackTimeout` dans les options de `io(...)` et appeler `socket.emitWithAck(...)` directement pour conserver le type de réponse. | `npm.cmd run build` est passé après la correction. |
| Les tests Socket.IO tournaient, mais `tsc` rejetait `node:events.once(socket, ...)` avec `TS2769`. | Pour un client Socket.IO, envelopper `socket.once(...)` dans une promesse typée et traiter `connect_error`. Garder `node:events.once` pour les vrais `EventEmitter`, par exemple le serveur HTTP. | Les tests Vitest, la compilation et le parcours Playwright sont passés après la correction. |
| Un test de non-diffusion recevait encore la dernière mise à jour ; un parcours à deux navigateurs pouvait envoyer une intention périmée après un clic sur l'autre page. | Attendre explicitement la diffusion sur le socket ou dans l'interface observés : un clic ou un acquittement sur un autre client n'est pas une barrière de réception. | Dans #7, attendre la désignation de J1 avant d'espionner le rollback et le statut de l'hôte dans Firefox avant de confirmer le prêt de l'invité. |
| La première diffusion reçue par un autre socket peut encore être celle d'une action précédente, même après l'acquittement de cette action. | Avant d'émettre, attendre sur chaque socket la révision exacte visée ; ignorer les autres diffusions et retirer les écouteurs après réception, annulation ou expiration. | Dans #54, les tests à 2–5 sièges vérifient la révision et le contenu des vues reçues à la désignation de J1 et au lancement. |
| Un import d'image hors de `apps/web` doit aussi fonctionner en développement avec la liste explicite `server.fs.allow` de Vite. | Autoriser le fichier précis, pas tout le dépôt ni le dossier des sources officielles. `vite/client` déclare déjà les imports WebP. | Pour #54, Vite lancé sur un port éphémère a servi le module d'import et le WebP source avec le type `image/webp` ; le parcours navigateur couvre le build compilé. |

## À garder en tête pour la suite

- Sous PowerShell, utiliser `npm.cmd` ou `opencode.cmd` si l’exécution des scripts `.ps1` est bloquée. Pour le test entre navigateurs, installer Chromium et Firefox via `npx.cmd playwright install chromium firefox`, puis compiler avant `npm.cmd run test:e2e` : le test sert les fichiers compilés.
- L’édition **Lucky Duck Games FR `LKY WWR-R01-FR`** et la désignation du premier joueur par l’hôte après accord de la table sont consignées dans [`rules.md`](rules.md) et [`docs/decisions.md`](docs/decisions.md). La [recette documentaire de #2](docs/rules-coverage.md#recette-documentaire-de-la-mise-en-place) valide des sous-périmètres précis du livret, sans établir le tirage de la boîte ni la conformité de son matériel. Distinguer les bilans par étape (p. ex. Paris pris à A, pas décompte après K) et ne pas importer de correctifs anglophones sans preuve d'applicabilité FR.
