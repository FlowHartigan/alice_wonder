# Mémo technique — Wonderland’s War Web

À consulter avant de commencer une issue ou de retenter une commande qui a échoué. Pour chaque nouveau problème utile à retenir, noter le symptôme, la cause si elle est connue, la correction et la vérification. Signaler explicitement les blocages encore ouverts.

## Problèmes rencontrés

| Symptôme | Correction ou précaution | Vérification |
|---|---|---|
| Les instructions mentionnaient GitLab alors que le projet est sur GitHub. | Vérifier `git remote -v` avant toute écriture distante. Utiliser `gh` avec `--repo FlowHartigan/alice_wonder` lorsque la commande le permet. | `origin` et `gh repo view` ont confirmé le même dépôt. |
| Git indiquait `No commits yet` et `origin/main [gone]` avant la publication du socle [#1](https://github.com/FlowHartigan/alice_wonder/issues/1). | Vérifier les branches réellement publiées avec `git ls-remote --heads origin`. Les issues peuvent être créées sans branche, mais une PR attend une base publiée. | **Résolu :** `git fetch origin main` puis `git rev-parse origin/main` ont confirmé le socle `5bfa697` pour [#37](https://github.com/FlowHartigan/alice_wonder/issues/37). |
| `user.name` et `user.email` ne sont pas configurés pour créer un commit. | Fournir `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_COMMITTER_NAME` et `GIT_COMMITTER_EMAIL` dans le processus qui exécute Git (identité autorisée et adresse GitHub `noreply`). Ne modifier aucune configuration Git. | Le commit de [#37](https://github.com/FlowHartigan/alice_wonder/issues/37) a été créé avec ces variables ; `git show` confirme l’auteur et le committer, et `git config --get` ne renvoie toujours aucune des deux clés. |
| L’appel `task` a renvoyé `Unknown agent type: github-issue`, alors que l’agent est configuré. | Distinguer les agents reconnus par OpenCode des types exposés par l’outil `task` de la session. Redémarrer OpenCode après modification de `.opencode/`. Si le type nommé est toujours indisponible, déléguer à un type disponible avec le rôle du fichier agent explicite et ne pas présenter ce relais comme un appel natif. | `opencode.cmd agent list` reconnaît les trois agents ; le relais `general` a permis de créer et de vérifier le backlog. |
| Une session en mode Plan ne permettait pas d’appliquer les fichiers. | Passer en mode **Build** avant d’écrire (`Tab` dans le terminal OpenCode) et vérifier le mode affiché. | Les fichiers d’agents et la commande `/evolution` ont ensuite été chargés par OpenCode. |
| Le téléchargement du livret FR via `webfetch` dépassait la limite de 5 Mo ; la commande `python` ouvrait le raccourci Microsoft Store. | Télécharger le PDF officiel dans le dossier temporaire approuvé avec `curl.exe`. Pour les tableaux en pictogrammes, consulter la page rendue : l’extraction de texte ne suffit pas. | Pour [#2](https://github.com/FlowHartigan/alice_wonder/issues/2), le PDF en cache et la pièce jointe éditeur retéléchargée ont le même SHA-256. Lire le PDF comme pièce jointe locale a fourni le rendu : les pictogrammes p. 5 ont été comptés visuellement. Ni le PDF ni son rendu ne sont ajoutés au dépôt. |
| Sous Windows PowerShell 5.1, le texte français passé par un pipe à Node peut perdre ses accents et tirets Unicode. | Avant d'envoyer du texte à une commande native sur son entrée standard, utiliser `$OutputEncoding = [System.Text.UTF8Encoding]::new($false)` dans le processus courant. | Node a reçu `Éclats — 2J` intact avec ce réglage. |
| PowerShell traite aussi l’apostrophe typographique `’` comme un délimiteur dans une chaîne entre apostrophes. | Reformuler le message de commit sans apostrophe ou utiliser des guillemets doubles. Pour un corps de PR Markdown, utiliser `gh pr create --body-file`. | Commit de #6 lancé avec un titre sans apostrophe et PR préparée à partir d’un fichier UTF-8. |
| Docker n’était pas disponible dans le `PATH` pendant le prototype. | Pour la recette locale, utiliser SQLite via `node:sqlite` et la version Node du projet (`>=24`). Voir `docs/decisions.md` pour la cible PostgreSQL. | Le test de réouverture de la base a retrouvé la place, le statut et l’idempotence. |
| TypeScript signalait `TS7053` après `socket.timeout(...).emitWithAck(...)` : la réponse devenait `any`. | Pour les appels à délai commun, régler `ackTimeout` dans les options de `io(...)` et appeler `socket.emitWithAck(...)` directement pour conserver le type de réponse. | `npm.cmd run build` est passé après la correction. |
| Les tests Socket.IO tournaient, mais `tsc` rejetait `node:events.once(socket, ...)` avec `TS2769`. | Pour un client Socket.IO, envelopper `socket.once(...)` dans une promesse typée et traiter `connect_error`. Garder `node:events.once` pour les vrais `EventEmitter`, par exemple le serveur HTTP. | Les tests Vitest, la compilation et le parcours Playwright sont passés après la correction. |
| Un test de non-diffusion recevait encore la dernière mise à jour ; un parcours à deux navigateurs pouvait envoyer une intention périmée après un clic sur l'autre page. | Attendre explicitement la diffusion sur le socket ou dans l'interface observés : un clic ou un acquittement sur un autre client n'est pas une barrière de réception. | Dans #7, attendre la désignation de J1 avant d'espionner le rollback et le statut de l'hôte dans Firefox avant de confirmer le prêt de l'invité. |
| La première diffusion reçue par un autre socket peut encore être celle d'une action précédente, même après l'acquittement de cette action. | Avant d'émettre, attendre sur chaque socket la révision exacte visée ; ignorer les autres diffusions et retirer les écouteurs après réception, annulation ou expiration. | Dans #54, les tests à 2–5 sièges vérifient la révision et le contenu des vues reçues à la désignation de J1 et au lancement. |
| Un import d'image hors de `apps/web` doit aussi fonctionner en développement avec la liste explicite `server.fs.allow` de Vite. | Autoriser le fichier précis, pas tout le dépôt ni le dossier des sources officielles. `vite/client` déclare déjà les imports WebP. | Pour #54, Vite lancé sur un port éphémère a servi le module d'import et le WebP source avec le type `image/webp` ; le parcours navigateur couvre le build compilé. |
| Un locator Playwright `/2 joueurs/` est devenu ambigu depuis l'ajout d'un rappel de règle pour cet effectif. | Cibler le libellé complet du récapitulatif, sans désambiguïser par l'ordre des éléments. | Le parcours Chromium + Firefox de #59 passe avec un motif ancré sur le récapitulatif du salon. |
| Le relevé temporaire TTS EN contient six Quêtes par Région ; rien ne garantit cette ventilation en FR. | Pour le retrait régional 2J, filtrer par Région d'Exploit, jamais par nombre de cartes retirées. Ne dériver ni la Région de l'ID, ni les critères du cache. | #61 teste des volumes inégaux ; [#65 autorise le paquet web v1 uniquement pour ce retrait](docs/rules-coverage.md#paquet-web-v1-et-vérification-fr). #10 reste ouverte pour le paquet et les critères FR. |
| Réutiliser la sortie de `initialRegionScores.safeParse` dans le retrait ferait perdre l'identité des placements. | Contrôler le succès du schéma strict de #59, puis filtrer les objets d'origine en lecture seule. | #61 vérifie les références et la conservation des six marqueurs. |
| Enregistrer plusieurs copies du retrait risquerait de désynchroniser la Quête révélée, la Région et son marqueur à la reprise. | En v6, garder l'affectation d'origine et un seul ordre de Quêtes versionné, dont la tête fixe la révélation. Dériver sans RNG ; ne pas importer le point d'entrée `lobby-storage` dans le client. | #65 compare les snapshots et les vues à la reprise et au rejeu, y compris après migration. |
| Une source discrète sur `2 ** 32` valeurs répartie avec `floor(fraction * 6)` ne rend pas exactement les six indices équiprobables. | Garder la même interface de hasard injectable et choisir pour la source serveur un nombre d'échantillons multiple de six. En v7, persister le résultat et la version, jamais un second état de la Région. | #69 couvre les six indices, la migration et la dérivation de la Région sans hasard au redémarrage. |
| `opencode.cmd run --agent github-issue` ne lance pas le sous-agent : la CLI retombe sur l'agent principal. | Si `task` n'est pas exposé, lancer `opencode.cmd run --agent build` depuis le worktree et lui demander un appel `Task` explicite au sous-agent nommé, dans un périmètre précis. | Pour #73, la sortie affiche l'appel à `implementation` et renvoie ses modifications et résultats de tests. |
| Sous Firefox Playwright, `locator.allTextContents()` sur les titres de Quêtes a fait échouer le parcours par `Page crashed` de façon reproductible. | Pour une pioche déterministe, vérifier les titres attendus depuis le jeu de test directement avec `expect(locator).toHaveText(liste)` ; pas d'évaluation DOM en bloc pour extraire ces chaînes. | Le même parcours Chromium + Firefox de #14 passe et contrôle les deux titres avant/après reprise. |
| Après remplacement d'un socket simulé, la carte des vues capturées garde sa dernière vue avant déconnexion. | Réinstaller l'écouteur `lobby:update` sur le socket de remplacement avant `lobby:resume` ; le reçu de reprise ne remplace pas une diffusion dans le test. | Les parcours #76 à 3–5J comparent la diffusion K capturée à la vue de reprise sur chaque socket, y compris celui remplacé. |
| Sur le plateau à 320 px, la puce droite des Chefs recouvrait « Premier combat » au Comté (2J, Jardin écarté, dé 1). Le marqueur de combat conserve une largeur de texte minimale alors que les positions suivent la taille du WebP. | Sur un plateau étroit, empiler les deux puces vers le dé imprimé du Bout de Table pour dégager le côté Comté, sans déplacer les autres repères ni supprimer la liste accessible. | Le scénario Playwright déterministe de la PR #79 reproduit le chevauchement avant correction et vérifie ensuite à 320 et 280 px la visibilité des repères et la séparation de leurs boîtes. |
| La revue d'un worktree temporaire a demandé à lire `.git/worktrees` dans le checkout principal, hors du périmètre de permissions du sous-agent. | Relire la PR publiée avec `gh pr diff` et demander explicitement `gh pr view --json headRefOid` (la vue par défaut ne donne pas le SHA exact). Ne pas élargir les permissions au checkout principal. | Sur #84, `gh pr view --json headRefOid` confirme la tête distante, et `gh pr diff` fournit les changements sans accès direct aux métadonnées Git locales. |
| Sous Windows, Playwright ne parvient pas à démarrer Firefox (`spawn UNKNOWN`) ; un cache navigateur neuf ne change rien. | Sur ce poste, Windows a confirmé que sa stratégie de contrôle des applications bloque l’exécutable Firefox de Playwright. Une fois le blocage confirmé, ne pas réessayer sur ce poste : relancer les scénarios Firefox dans un environnement autorisé, sans contourner la stratégie ni modifier les tests. | **Recette [#85](https://github.com/FlowHartigan/alice_wonder/issues/85) :** 4 parcours Chromium seuls réussis sous Windows ; le blocage local de Firefox demeure. Après intégration de la CI #3, les [8 parcours passent sous Ubuntu 24.04](https://github.com/FlowHartigan/alice_wonder/actions/runs/44894899937), dont le parcours mixte et les 3 parcours Firefox seuls. |
| À 280 px, le scénario passait sous Chromium Windows, mais le [run Ubuntu 24.04](https://github.com/FlowHartigan/alice_wonder/actions/runs/44893741690) détectait un chevauchement au Comté. Sur un plateau de 214 px, la place disponible pour le badge centré était d’environ 58 px : sa boîte mesurait 56,2 px avec la police système Windows et 64,5 px avec DejaVu Sans Bold du paquet Ubuntu (mesure locale en changeant uniquement la police). | Pour un plateau d’au plus 15 rem, décaler de 5 px vers la droite uniquement le badge « Premier combat » au Comté. Ni la taille du texte, ni les repères des Chefs près du dé imprimé ne changent. | Avec DejaVu, à 280 px, l’intersection horizontale de 3,25 px laisse place à un espace de 1,75 px. À 320 px, l’espace reste de 3,39 px sans décalage. Texte entier visible aux deux tailles sur les captures locales, et scénario Playwright inchangé. |
| Sur Ubuntu, le scénario Playwright du plateau à 320 px (« les Chefs au Bout de Table ne recouvrent pas Premier combat au Comté ») a dépassé le délai de test de 30 s. Cause inconnue. | Si cela se reproduit, conserver la trace Playwright, le rapport et les logs CI ; comparer deux tentatives sur le même SHA avant de modifier le délai. | [PR #93](https://github.com/FlowHartigan/alice_wonder/pull/93), SHA `ba42c465d763368b89992c53db129ebae2c614ae` : [7/8 à la première tentative](https://github.com/FlowHartigan/alice_wonder/actions/runs/44923388415/job/136904054776), puis [8/8 à la seconde](https://github.com/FlowHartigan/alice_wonder/actions/runs/44923388415/job/136904695929), sans changement. |

## À garder en tête pour la suite

- Lors des essais du socle CI #3 (PR #87), Firefox Playwright a aussi échoué au lancement sous Windows avec `spawn UNKNOWN` malgré l’installation du navigateur. La cause n’a pas été établie lors de ces essais ; la CI Ubuntu de la PR #87 a exécuté avec succès les parcours Firefox du socle.
- Lors d'une nouvelle version SQLite, distinguer dans les tests la version d'entrée des fixtures, la version intermédiaire ciblée par les triggers de rollback et la version courante attendue. Une fixture dérivée d'un état courant doit retirer les champs ajoutés depuis sa version et passer par son propre schéma strict. Dans #90, la chaîne v9/v10 garde le trigger v11, et le cas v11 vérifie le rollback de la deuxième écriture v12.
- Sous PowerShell, utiliser `npm.cmd` ou `opencode.cmd` si l’exécution des scripts `.ps1` est bloquée. Pour le test entre navigateurs, installer Chromium et Firefox via `npx.cmd playwright install chromium firefox`, puis compiler avant `npm.cmd run test:e2e` : le test sert les fichiers compilés.
- L’édition **Lucky Duck Games FR `LKY WWR-R01-FR`** et la désignation du premier joueur par l’hôte après accord de la table sont consignées dans [`rules.md`](rules.md) et [`docs/decisions.md`](docs/decisions.md). La [recette documentaire de #2](docs/rules-coverage.md#recette-documentaire-de-la-mise-en-place) valide des sous-périmètres précis du livret, sans établir le tirage de la boîte ni la conformité de son matériel. Distinguer les bilans par étape (p. ex. Paris pris à A, pas décompte après K) et ne pas importer de correctifs anglophones sans preuve d'applicabilité FR.
